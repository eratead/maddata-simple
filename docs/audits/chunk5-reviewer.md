## High

### H1. Stale `client->agency` reference — broken column read
`resources/views/campaigns/index.blade.php:209`
```blade
<span class="text-xs text-gray-500">{{ $campaign->client->agency ?? '' }}</span>
```
Migration `2026_03_22_000005_drop_agency_string_from_clients_table.php` drops
the `clients.agency` column. Accessing `->agency` on a Client now silently
returns `null` (the relationship `agency()` returns the Agency model, so this
evaluates to the Agency Eloquent object and the `?? ''` does nothing sensible
— it casts/renders an object). The `th` is even `hidden` but this still
executes and confuses/pollutes output.
**Fix:** Replace with `{{ $campaign->client->agency?->name ?? '' }}` or remove
the column/row entirely since the `<th>` is already marked `hidden`.

### H2. `cascadeOnDelete` on nullable Creatives.campaign_id FK
`database/migrations/2026_02_02_112057_add_campaign_id_to_creatives_table.php:15`
```php
$table->foreignId('campaign_id')->nullable()->constrained('campaigns')->cascadeOnDelete();
```
The column is nullable (so creatives can exist detached), but cascade delete
will still wipe them when the campaign is deleted. For a nullable FK on an
asset-bearing entity, `nullOnDelete()` is usually the intended behaviour so
orphaned creatives aren't silently removed with their files on disk.
**Fix:** Confirm business rule. If creatives should survive campaign deletion,
switch to `nullOnDelete()`. Otherwise document that campaign deletion destroys
all linked creatives + files.

### H3. Privilege-escalation risk in `admin.roles.update` route binding
`routes/web.php:85` — `Route::resource('roles', …)` has no `is_protected`
gating. While a `is_protected` column exists on `roles`
(`2026_03_25_085724_add_is_protected_to_roles_table.php`), the route allows
editing any role by id. Enforcement must live in the controller / FormRequest.
**Fix (verify):** Confirm `RoleController::update/destroy` rejects
`is_protected=true` roles and that a lower-privileged role holder cannot grant
permissions greater than their own (tie-in with `Role::sort_order`).

## Medium

### M1. Inline onclick handlers bypass Alpine/CSP
- `resources/views/creatives/edit.blade.php:143` — `onclick="if(confirm(…)) …submit()"`
- `resources/views/creatives/edit.blade.php:246` — same pattern
- `resources/views/admin/audiences/index.blade.php:87-95,201` — `onclick="audienceFilter.…"`, `onclick="audienceModal.openEdit(…)"`
- `resources/views/admin/campaign_changes/show.blade.php:49` — `onclick="toggleAll(this)"`
- `resources/views/campaigns/index.blade.php:246` — `onchange="this.form.submit()"`
- `resources/views/clients/index.blade.php:25` — `onchange="window.location.href=…"`
- `resources/views/admin/audiences/index.blade.php:65` — `<x-primary-button onclick="…">`

These bypass the project's standard Alpine `$dispatch('confirm-action', …)`
flow and force an `unsafe-inline` script-src. `confirm()` is also inconsistent
with the custom `<x-confirm-dialog />` UX used everywhere else in the app.
**Fix:** Replace `confirm()` usages with the `confirm-action` dispatch pattern.
Move `audienceFilter` / `audienceModal` globals into Alpine `x-data` so
handlers become `@click=` / `@change=`.

### M2. `users.index` "No role" filter uses string literal `"null"`
`resources/views/users/index.blade.php:99` — `<option value="null">No role</option>`
The Alpine filter compares `String(u.role_id) === this.filterRole`, but
`role_id` is `null` on unassigned users, so `String(null) === 'null'` does
accidentally match. It works, but relies on string coercion quirks.
**Fix:** Handle explicitly: `this.filterRole === 'null' ? u.role_id === null : …`.

### M3. Components are skipped inside `<x-campaign.details-card>`
`resources/views/components/campaign/details-card.blade.php:27-29` hand-rolls
`<input type="text" …>` with a long inline Tailwind class string (`$inputClass`)
instead of using `<x-text-input>` and `<x-input-label>` (which the
create-form at `resources/views/campaigns/create.blade.php` uses). Visual
result is nearly identical but the two forms will drift. Same pattern in
`schedule-card.blade.php`, `sizes-accordion.blade.php`.
**Fix:** Use the existing `<x-text-input>` and `<x-input-label>` components,
or delete them in favour of a single canonical style. Don't keep both.

### M4. External CSS/JS loaded outside Vite
`resources/views/campaigns/edit.blade.php:1-2` pulls Leaflet CSS/JS from
`unpkg.com` into the top-level of a Blade view. This breaks CSP/asset
bundling, leaks a third-party request on every edit page load, and ships
Leaflet even when the targeting accordion is collapsed.
**Fix:** `npm i leaflet`, import via Vite, lazy-load when the geo tab opens.

### M5. Long `x-data` literals embedded in page-level Blade
`resources/views/users/index.blade.php:20-78`,
`resources/views/campaigns/edit.blade.php:97-496` (>400-line `@push('scripts')`).
The patterns work, but are hard to test/debug and mix PHP-to-JS transport with
app logic. Extract to named Alpine components in a `resources/js/alpine/`
module and register via `Alpine.data('userIndex', …)`.

### M6. `users.index` exposes entire user list to the client
`resources/views/users/index.blade.php:20-32` emits the full user list
(name, email, agencies, clients, edit URLs) via `@js($users->map(…))`. Filtering
is done client-side. Fine on the admin page, but:
- consider server-side pagination once user count grows;
- audit that only admins reach this route (confirmed by `admin` middleware).

### M7. `personal_access_tokens` `name` column is `TEXT`
`database/migrations/2026_03_05_170243_create_personal_access_tokens_table.php:21`
uses `$table->text('name')` — this deviates from Sanctum's default
(`string('name')`) and prevents indexing/ordering on name. Legacy migration
from staging is noted in memory; worth aligning schema.

### M8. `sessions` table defined twice with divergent logic
- `0001_01_01_000000_create_users_table.php:33-40` creates it unconditionally.
- `2026_03_25_125623_create_sessions_table.php:11` uses
  `if (Schema::hasTable('sessions')) return;`.
Running `migrate:fresh` succeeds, but a `migrate:rollback` will drop `sessions`
at the later migration yet the earlier migration's `down()` also calls
`Schema::dropIfExists('sessions')`. The later migration's `down` will blow
away the table when rolling back beyond it even if the original create still
needs it. Recommend deleting the `sessions` creation from the users migration
or from the newer one.

## Low / Nitpicks

### L1. Duplicate `agency_user` pivot schema inconsistency
`2026_03_22_000003_create_agency_user_table.php` creates with `role` column,
then `2026_03_23_073504_update_agency_user_add_access_all_clients.php` drops
`role`, adds `access_all_clients` **and adds timestamps**. Consolidate into a
single source-of-truth migration once staging/prod are in sync (or leave a
comment explaining the deploy-ordering constraint).

### L2. `activity_logs.status` defaults to `pending` with no check constraint
`2026_02_16_153953_add_status_to_activity_logs_table.php:15` — consider a
CHECK/enum or constants-only contract. Without one, rogue values are possible.

### L3. `campaigns.required_sizes` stored as comma-delimited text
`2026_02_10_132311_add_required_sizes_to_campaigns_table.php:15` uses `text`.
Since many other list-typed fields use `json` (`targeting_rules`,
`roles.permissions`, `activity_logs.changes`), converting to a JSON column
would align the codebase.

### L4. `campaigns.expected_impressions` / `budget` as signed INTEGER
`2025_05_12_055140_create_campaigns_table.php:19-20` use `integer()` (signed,
~2.1B max). For NIS/ILS budgets (currency in minor units) or very large
impressions, consider `unsignedBigInteger()`. Also `default(0)->nullable(true)`
is a contradictory signal — pick one.

### L5. `placements_data.name` indexed standalone
`2025_05_12_062052_create_placements_data_table.php:16` has `string('name')
->index()`. Combined with the new `placements_data_campaign_date_index`, the
single-column `name` index may be redundant depending on queries. Verify with
`EXPLAIN` once data is populated.

### L6. Accessibility: `<label>` without `for` in custom combobox dropdowns
`campaigns/create.blade.php:74`, `campaigns/index.blade.php` filter,
`details-card.blade.php:55` — the triggering `<button>` is not associated with
its visible `<label>` / no `aria-labelledby`, no `role="combobox"`,
`aria-expanded`, `aria-controls`. Screen-reader users get a plain button.
**Fix:** Add `role="combobox"`, `aria-expanded="$open"`, `aria-controls` and
connect the label via `id` + `aria-labelledby`.

### L7. Missing `aria-label` on icon-only action buttons
Many tables (e.g. `campaigns/index.blade.php:252-275`, `clients/index.blade.php:91-118`)
use icon-only buttons with a `title=` attribute. Add `aria-label` so keyboard
/ AT users get the label without hover.

### L8. Keyboard nav in custom dropdowns
Combobox dropdowns (`campaigns/create.blade.php:77-127`, `details-card.blade.php`)
do not support arrow keys / Enter / Home-End. Consider an `@keydown.arrow-down`
handler on the `<input>` that moves focus across `<button>` items in the list.

### L9. `x-cloak` reliance without CSS
Several components use `x-cloak` and `style="display:none"` side-by-side
(e.g. `admin/audiences/index.blade.php:28`, `campaigns/create.blade.php:94`).
Ensure `app.css` ships `[x-cloak]{display:none!important}`; otherwise
`x-cloak` alone is a no-op.

### L10. Mixed button-component usage
`resources/views/components/primary-button.blade.php` is used on index pages,
but `campaigns/edit.blade.php` and parts of the dashboard use inline
`<button class="…bg-[#F97316]…">`. Pick one.

### L11. Rubik font vs. design-system "Inter"
`layouts/app.blade.php:12-14` loads Rubik but `docs/project_context.md` and
the design system reference Inter. Either update the docs or align the font.

### L12. Inline `<style>` in layout
`layouts/app.blade.php:13-20` declares a `<style>` block with custom CSS
(`.nav-active`, scrollbar styles). CLAUDE.md forbids custom CSS — these
declarations could be moved to `tailwind.config.js` as a component class or
rewritten as utility classes (`bg-gradient-to-r from-…`).

### L13. Duplicate `agency_user` inline pivot migration
`2026_03_22_000003_create_agency_user_table.php` + the `update` migration
creates timestamps separately. On a fresh DB the pivot starts without
timestamps until the second migration runs — cascade effects are minor but
noted.

### L14. `clients` table missing `unique(name, agency_id)` / index on agency_id
`2025_05_07_120919_create_clients_table.php` — no uniqueness on `(name,
agency_id)`. Many agencies may have clients of the same name, but duplicates
within the same agency are probably unintentional. Also `agency_id` FK is not
explicitly indexed (Laravel FKs auto-index, so verify in MySQL).

### L15. Hebrew shekel currency hard-coded in Blade
`campaigns/create.blade.php:143` shows `Total Budget (₪)` while
`details-card.blade.php:100` shows `Total Budget (NIS)` — normalize.

### L16. `admin/audiences/index.blade.php:201` passes unescaped name into inline onclick
The JSON encode does escape quotes, but embedding user-editable `$audience->name`
inside an `onclick="` attribute is still fragile if the name contains `</script>`
fragments. Prefer the Alpine `@click="openEdit({{ Js::from($audience) }})"` form.

### L17. Route binding not scoped
`routes/web.php:101-104` — `campaign-changes/{campaign}` and nested
`log/{log}` not using implicit scoping (`->scopeBindings()` or
`{campaign:id}/logs/{log:campaign_id}`). If log-to-campaign integrity matters,
scope the log to its parent campaign.

### L18. `audiences.main_category` + `audiences.sub_category` are individually indexed
`2026_03_02_000001_create_audiences_table.php:14-15` — a composite
`(main_category, sub_category)` index would serve the nested filter UI better.

### L19. Campaign observer-generated activity logs: no index on `subject_type+subject_id`
`2026_02_08_144832_create_activity_logs_table.php:18` — `nullableMorphs` adds
a combined index by default, so this is fine, but the `user_id` column is not
indexed beyond the FK.

## Positive observations

1. **Consistent use of `@js()` / `Js::from()`** for Alpine data across all
   pages — CLAUDE.md escaping rule is well-respected. Only one `{!! !!}` usage
   in the whole code base (`2fa-setup.blade.php`) and it's justified
   (server-generated SVG).
2. **Confirm-dialog pattern** (`$dispatch('confirm-action', …)`) is used
   broadly and consistently — good reusable UX primitive.
3. **Foreign-key hygiene** is excellent: every FK uses `constrained()` with
   either `cascadeOnDelete()` or `nullOnDelete()` chosen deliberately.
4. **Pivot naming** follows Laravel convention (`client_user`, `agency_user`,
   `campaign_audience`) — singular, alphabetical.
5. **Performance indexes migration** (`2026_03_22_184627`) is thoughtful —
   composite `(client_id, status)`, `(campaign_id, report_date)`,
   `(campaign_id, status)` target real query paths.
6. **UNIQUE constraint on `campaign_data (campaign_id, report_date)`** is
   correctly in place and matches the CLAUDE.md contract.
7. **Layout uses `bg-gray-50`** and `#F97316` accent per design system.
8. **Route protection is strict**: all web routes live inside `auth` group;
   admin routes under `admin` middleware; campaign-manager tokens isolated;
   Sanctum API guarded by `check-token-expiry` + `ability:reports:read`.
9. **`EnsureUserIsAdmin`** + middleware aliases keep controllers clean; no
   inline role checks leak into routes.
10. **Migration down() methods** are present on every migration and are
    symmetrical. The data-migrating `drop_agency_string_from_clients_table`
    has a safe idempotent `down()`.
11. **`nullableMorphs('subject')`** on `activity_logs` allows audit trails
    across entities without a proliferation of nullable FKs.
12. **Component reuse is reasonable** — campaign card sub-components
    (`details-card`, `schedule-card`, `sizes-accordion`, `targeting-accordion`,
    `creatives-accordion`, `audiences-accordion`) cleanly decompose the edit
    page.
13. **Registration disabled** in `routes/auth.php` is documented and
    intentional for the managed-service SaaS model.
14. **`throttle:10,1`** on the two AI endpoints prevents abuse.
15. **CSRF + `@method('DELETE')`** used consistently on every destructive
    form.
